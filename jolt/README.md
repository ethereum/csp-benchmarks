# Jolt benchmarks

The benchmark uses Jolt commit [`2a85f76476daee22dea4234a5fa10c4c89e732be`](https://github.com/a16z/jolt/commit/2a85f76476daee22dea4234a5fa10c4c89e732be), the latest commit on `main` before 30 September 2026 ended in Asia/Taipei. Cargo fetches the ERE adapter from [revision `c9527535`](https://github.com/Client-Side-Proving/ere/commit/c9527535fb7976aee30727c3d3bd87a792c423d1) of the CSP fork.

## Installation

Install the CLI and guest target used by `.github/actions/install-jolt/action.yml`:

```bash
rustup toolchain install 1.95 --component rust-src
rustup target add riscv64imac-unknown-none-elf --toolchain 1.95
cargo +1.95 install --git https://github.com/a16z/jolt.git \
  --rev 2a85f76476daee22dea4234a5fa10c4c89e732be jolt --locked --force
```

## Proof mode and statements

The adapter enables Jolt's `host` and `zk` features and proves with the Dory PCS and BlindFold. The guest input is a length-prefixed byte stream in untrusted advice. SHA-256, Keccak-256 and BLAKE3 guests publish their 32-byte digest; verification compares the proved output with the expected digest generated by the benchmark. The ECDSA guest reads the message digest, signature and public key from untrusted advice and publishes a success byte. The verifier checks that success output; the message digest and public key are private in this integration.

## Benchmarking

After changing the Jolt revision, remove the cached compiled programs so the harness builds guests with the current compiler and dependencies:

```bash
for target in sha256 keccak blake3 ecdsa; do
  rm -f "jolt/guest/$target/target/$target.bin"
done
BENCH_INPUT_PROFILE=reduced cargo bench -p jolt
```

The memory binaries load the compiled guests produced by the harness and run preprocessing and proving.

Run the integration test to compile each guest, prove and verify a small input, and check altered outputs and invalid ECDSA input rejection:

```bash
cargo test -p jolt benchmark_proof_roundtrips -- --ignored --test-threads=1
```
