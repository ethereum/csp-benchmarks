# P-256 ECDSA validation

## Caller preconditions

The public interface is `r[4]`, `s[4]`, `msghash[4]`, and `pubkey[2][4]`, using little-endian 64-bit limbs. The circuit validates the finite public key, reduces the prehash modulo the group order, and constrains `R.x mod n = r` for a finite verification result. Fake-GLV decomposition values are derived during witness generation and constrained inside the circuit.

The arithmetic templates require valid curve points. `P256AddComplete` and the Straus table require canonical finite x and y coordinates. `P256QuadAddComplete` accepts and returns accumulator coordinates modulo p as eight bounded 32-bit limbs per coordinate; its table operand is canonical. Infinity is `(x,y,isInf) = (0,0,1)`. The caller constrains selector bits to Boolean values. The ECDSA circuit establishes these preconditions before table construction.

## Regression commands

Run from the repository root with Circom 2.2.3, Node, SnarkJS 0.7.5, and Python with `cryptography`. The Node script uses an existing local or global SnarkJS installation.

```sh
mkdir -p target/p256-checks/ecdsa_p256_32 target/p256-checks/point_ops target/p256-checks/quad_mod target/p256-checks/straus
circom circom/circuits/ecdsa/ecdsa_p256_32.circom --O2 --r1cs --wasm --sym -o target/p256-checks/ecdsa_p256_32
circom circom/tests/p256/point_ops.circom --O2 --r1cs --wasm --sym -o target/p256-checks/point_ops
circom circom/tests/p256/quad_mod.circom --O2 --r1cs --wasm --sym -o target/p256-checks/quad_mod
circom circom/tests/p256/straus.circom --O2 --r1cs --wasm --sym -o target/p256-checks/straus
python3 circom/tests/p256-reference.py target/p256-checks/vectors.json
node circom/tests/p256-circuits.cjs target/p256-checks target/p256-checks/vectors.json
cargo test -p circom --lib ecdsa_p256 --locked --offline
cargo fmt --all -- --check
git diff --check
```

The Python reference checks the comb tables, scalar decomposition, quotient/carry bounds, and exceptional scalars, and generates independently verified signatures and invalid inputs. The Node tests check witnesses against the R1CS and reject mutations of outputs, selectors, signature inputs, slopes, and modular certificates. Cases cover doubling, cancellation, infinity, noncanonical accumulator coordinates, sentinel public keys, and hash/signature boundaries.

## Validation boundaries

Circuit compilation, the reference checks, and WASM/native witness tests run without a zkey. Native tests require local native dependencies; their build scripts may download material even with Cargo `--offline`. Groth16 proving, verification, and benchmark timings require a zkey matching the compiled circuit. The benchmark target requires `circom-ecdsa-p256-bench` and a matching published key; no matching key is present in the manifest.

The P-256 table and accumulator handle equal points, inverse points, and infinity. The secp256k1 fake-GLV loop uses strict affine additions and rejects some valid signatures on equal-x additions. Constraint comparisons must account for this coverage difference. The regressions provide executable coverage, not a formal proof of this Circom implementation.
